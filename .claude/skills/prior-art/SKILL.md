# もうあるよチェック(prior-art)

オーナー指示(2026-10-21)。きっかけ: GEO は考え方としては MDA(Mass Data Analysis。大量のハンドから母集団の癖を見つけて突く)と同じなのに、解説ページは「GTOを超える」と書き、誰も指摘しないまま公開されていた。オーナーに聞かれて初めて出た。
**聞かれてから答えるのでは遅い。手を付ける前に自分から調べて、先に言う。**

## いつ使うか

依頼の種類を問わず、作業に手を付ける前に毎回。調べる深さだけを作業の大きさで変える。

| 作業の大きさ | 例 | やること |
|---|---|---|
| 大(必ず Web で調べる) | 新機能、新しい概念・用語、画面や仕組みの作り直し、料金・課金、戦略の理論、宣伝文句・LP・解説ページ | 下の手順をすべて |
| 中 | 既存機能の仕様の変更、操作の流れの変更 | 知っている範囲で照らし、怪しければ Web で確かめる |
| 小 | 文字の大きさ・色・小さな不具合 | 既存の定石(Apple の HIG、apple-design スキル等)と照らすだけ |

迷ったら大に倒す。

## 手順

1. **やろうとしていることを1行で言い直す**(「〇〇のために△△をする」)。仕組みの名前ではなく、中身で言う。
2. **既にあるものを探す。** WebSearch を同じターンに並べて投げる。探す先:
   - 競合・近いアプリ: Ten-Four(テンフォー)、GTO Wizard、GGPoker / PokerStars / WPT Global、PokerTracker / Hand2Note / HoldemManager、Upswing・Run It Once などの学習サイト、日本のポーカーアプリ・アミューズメント
   - ポーカーの既存の理論・手法・用語(英語で調べる。例: MDA, population tendencies, node locking, ICM, push/fold charts, TDA rules)
   - 一般的な設計・実装の定石(UI のパターン、マッチメイキング、レーティング、課金の設計など)
   - **失敗した例**(同じことをやってうまくいかなかったサービス・炎上・規約違反)
3. **違いを正直に見積もる。** 「同じ」「ほぼ同じ(違いは△△だけ)」「本当に新しい」のどれかに分ける。違いが作りの差(データの出どころ・見せ方・つながり)だけなら、そう書く。
4. **説明文も読む。** 既存の機能を触るなら、その機能を利用者にどう説明しているか(`apps/web/src/app/(content)/` の解説ページ、`lib/i18n.tsx` と `lib/locales/` の宣伝文句)を読む。言い過ぎ・理論の誤り・事業上の危うさ(景品表示法の誇大表示、賭博と誤解される表現、他社の商標)があれば、作業の範囲の外でも報告する。
5. **作業より先に伝える。** 報告の形は下。調べた結果が「本当に新しい」でも、何を探して見つからなかったかを一言添える。
6. オーナーが「それでも作る」と言ったら作る。止めるのが目的ではなく、知った上で決めてもらうのが目的。

## 伝え方(日本語。最初の段落に置く)

```
先に1点: これは既に〇〇としてあります(出典: …)。
違いは △△ だけです。/ 〇〇は □□ で失敗しています。
なので、□□ にするか、△△ を売りにするのがよいと思います。進めてよければ作ります。
```

- 出典の URL を付ける。記憶だけで言うときは「記憶ベースで未確認」と書く。
- 長い比較は表にする。結論を先に書く。
- 軽微な作業で何も見つからなかったときは、わざわざ書かない(ノイズにしない)。

## 例

- **GEO と MDA**: 「GTO の均衡+実プレイヤーの母集団データで乖離を突く」は MDA と同じ。違いは、データがアプリ内の母集団だけであること、GTO の表と並べて局面ごとの乖離を見せる道具であること、偏差値・ICM で絞れること、棋譜解析とつながっていること。「GTOを超える」は言い過ぎ。
- **フレンド対戦の途中着席**: TDA Rule 8(デッドボタン、BB イン、SB からは入れない)という既存の規則がある。自分で決めずに規則どおりに作る。
