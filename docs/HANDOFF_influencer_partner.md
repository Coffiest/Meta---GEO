# 引き継ぎ: インフルエンサー(ローンチパートナー)施策

2026-10-10 時点。オーナーと詰めて**確定した仕様**と、**実装の段取り・進み具合**をまとめる。
続きを作る人は、ここを読んでから着手すること。

## 1. 確定した仕様(オーナー承認済み)

### 報酬と割引

| 項目 | 内容 |
|---|---|
| 報酬の対象 | インフルエンサーのコードで**有料会員になった人**の支払い |
| 割引 | コードを使うと**初回の支払いが30%OFF**(2回目以降は定価) |
| 還元率 | **入金額(割引後・税込)の80%**。Stripe 手数料(3.6%)は当方が負担。返金・チャージバックは差し引く |
| 対象の支払い | その会員の**最初の3回分の支払い**(初月30%OFF → 2ヶ月目 → 3ヶ月目)。途中で解約したらそこまで。途中でプランを変えたら、実際の入金額の80% |
| 対象プラン | **3プランすべて**(シルバー ¥980 / ゴールド ¥1,380(主力)/ プラチナ ¥1,890) |
| 1人あたりの目安 | シルバー約 ¥2,100 / **ゴールド約 ¥2,980** / プラチナ約 ¥4,080(DM では % より金額で書く) |
| 期限 | **「ローンチパートナー特別レート」。2027年3月末までに加入した会員が対象**。以降の率は改めて決める |
| 支払い | **月末締め・翌月末払い。最低 ¥3,000**(未満は繰り越し)。振込手数料は当方負担。返金は翌月以降の報酬と相殺 |
| インフルエンサー本人 | **プラチナを3ヶ月無料**(管理者画面の既存の「無償付与」)。加入者が1人でも出たら延長 |
| 宣伝の方法 | **自由型**(実際に使って、面白いと思った点を自由に紹介してもらう) |

### コードの入れ方

- **Stripe の決済画面でコードを入れたときだけ**、そのインフルエンサーの紹介とみなす(リンクやアカウントへの紐づけはしない。オーナー選択)。
- コードは Stripe の**プロモーションコード**。インフルエンサーごとに1つ、何件でも発行・停止できる。`HIKARU30` のように読めるコードも指定できる。

### 不正・損失の対策(オーナー承認済み)

1. **有料会員になったことが一度も無い人だけ**がコードを使える(Stripe の `restrictions.first_time_transaction: true`)。既存の会員が解約→コードで入り直す抜け道を塞ぐ。
2. **インフルエンサー本人のアカウント・本人と同じカードでの加入は報酬の対象外**(無料体験の不正対策と同じ、カードの指紋 `card.fingerprint` で照合)。
3. 規約で**自分での購入・フォロワーへのキャッシュバック・クーポンサイトやポイントサイトへの掲載を禁止**。違反したらコードを停止できる。
4. **ステマ規制(2023年10月〜)**: 投稿の「#PR」などの広告表示を必須にする(責任を負うのは広告主=当方)。
5. 契約は **18歳以上**に限る。
6. 消費税は「扱いを変更することがある」と規約に1行入れる(いまは免税事業者の想定)。

### 未確定・保留

- **7日間の無料体験の削除**: オーナーは消したい意向。ただし「980円が700円くらいになった」という不具合の正体が未確認(コードに割引は無い。プラン変更の日割りの可能性が高い)。**Stripe の該当請求の明細を見てから決める**。
- **Vercel のプラン**: Hobby(無料)は商用利用禁止。課金しているので Pro が必要。オーナーに確認中。

## 2. 実装の段取り(小さく分けて1つずつ出荷)

| # | 中身 | 状態 |
|---|---|---|
| 1 | **コードの発行**(管理者画面: 名前・連絡先・メモ・本人のユーザーID・任意のコード → Stripe のクーポン+プロモーションコードを作り、台帳に記録。一覧・停止)+ **決済画面のコード入力欄**(Checkout に `allow_promotion_codes: true`) | **済(v4.196.0)**。管理者画面「インフルエンサーのコード」 |
| 2 | **報酬の台帳**(Webhook `invoice.paid` で1件=1行。`charge.refunded` はマイナスの行で打ち消し、元の行は書き換えない)+ 管理者の「今月いくら払うか」一覧・CSV・支払済みにする操作 | 未着手 |
| 3 | **インフルエンサー用の明細ページ**(本人専用の秘密 URL。日付・プラン・入金額・報酬・状態を1行ずつ。相手の名前は伏せ、請求書番号は末尾だけ) | 未着手 |

### 1 の設計メモ

- DB(新しいマイグレーション):
  - `Partner`: `id` / `name` / `contact`(X のアカウントなど)/ `note` / `code`(一意)/ `stripePromotionCodeId`(一意)/ `statementToken`(明細ページの秘密の鍵。3 で使う)/ `userId`(本人のアカウント。自己購入の除外用。任意)/ `active` / `createdAt`。
- Stripe(実装: `packages/server/src/partnerStripe.ts`):
  - クーポンは全員で共通の1つ(id `poker_art_partner_30_first_month_v1`、`percent_off: 30`、`duration: "repeating"`・`duration_in_months: 1`)。無ければ初回に作る(`stripePlans.ts` の価格と同じやり方)。
  - プロモーションコードはパートナーごと(`coupon` に上の id、`code`、`restrictions.first_time_transaction: true`、`metadata.partnerId`)。停止は `active: false`。
  - SDK は `stripe@17.7.0`(`promotionCodes.create({ coupon })` の形)。
- 無料体験との重なり: `once` だと体験中の ¥0 の請求で割引が使い切られるおそれがあるため、`repeating`(1ヶ月)にした。契約の開始から1ヶ月の間に来る有料の請求(体験ありなら7日目、なしなら初日)の1回だけが30%OFFになる。
- 管理者 API は `packages/server/src/adminApi.ts`(`/api/admin/partners` など)、画面は `apps/web/src/app/admin/page.tsx` に `components/admin/PartnerPanel.tsx` として足す(`FeedbackInbox` と同じ形)。

### 2 の設計メモ

- `PartnerCommission`: `partnerId` / `stripeInvoiceId` / `kind`("payment" | "refund")/ `userId` / `plan` / `amountPaid` / `commission` / `paymentIndex`(1〜3)/ `status`("pending" | "payable" | "paid" | "void")/ `voidReason` / `occurredAt` / `paidAt`。`(stripeInvoiceId, kind)` で一意(Webhook の再送で二重に数えない)。
- 判定: 請求書の discount のプロモーションコード → `Partner`。その契約で何回目の支払いか(1〜3。4回目以降は記録しない)。加入日が期限(2027-03-31)以内か。本人・同じカードなら `void`。
- 月末締め: 前月分の `pending` → `payable`。合計が ¥3,000 未満なら繰り越し。
- **Supabase の転送量のきまり(CLAUDE.md)を守る**: `select` の無い upsert・全件の findMany をしない。
